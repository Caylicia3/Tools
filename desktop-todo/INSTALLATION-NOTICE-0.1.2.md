# 0.1.2 安装问题说明

更新日期：2026-10-15。状态：正在排查，尚未发布程序修复。

此前“Windows 11 上的 360 提示问题已解决”的用户反馈不完整，现已撤回该验收结论。Windows 10 可以运行的已有反馈保留。

## 已知现象

- 0.1.2 安装器替换安装目录中的 DesktopTodo.exe 时，出现 MoveFile 失败、错误代码 5、拒绝访问。
- 创建桌面“日程管理”快捷方式时，出现 IPersistFile::Save 失败、0x80070005、拒绝访问。
- 360 文件防护提示的发起程序为安装器的临时进程，目标为本程序安装目录下的 DesktopTodo.exe。用户补充：卸载旧程序后重新安装，没有处理 360 提示，并在安装器报错后选择了“跳过此文件”。截图中默认操作为“阻止本次操作”；结合时间顺序，高度符合防护阻止导致替换失败的情况。快捷方式错误是否由同一防护造成，仍需重试或安装日志确认。

这与之前应用启动时的通知注册提示发生在不同阶段。默认托盘提醒不进行原通知入口注册，但不能保证安装器对程序文件和快捷方式的操作不被安全软件拦截。

## 遇到相同问题时

1. 不要选择“跳过此文件”后继续使用；取消此次安装，保留原数据目录。
2. 通过主面板右上角 × 完全退出旧程序，在任务管理器确认没有 DesktopTodo.exe；只最小化窗口仍会继续运行。
3. 重新使用 Release 提供的完整安装包安装到原程序目录，并沿用原数据位置；卸载过不代表原文件一定已全部删除，不要因此删除数据目录。
4. 仅在确认安装包来自本仓库且 SHA-256 与 Release 的校验文件一致后，才对目标确实为本程序 exe 或本程序快捷方式的预期安装操作选择仅允许本次；不要关闭全部防护或给整个磁盘加白名单。不确定时取消，先核对文件。
5. 如果明确允许后仍出现错误，保留安装日志继续排查文件占用、目录权限和快捷方式保护，不要直接修改系统目录权限或删除原日程数据。

可通过安装器官方的 /LOG="完整日志路径" 参数记录文件安装与错误步骤；/LOGCLOSEAPPLICATIONS 记录占用程序检测详情。日志可能包含 Windows 用户名和本机路径，回传前可查看；不要公开上传日程数据库。

官方参考：[Windows 错误代码](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--0-499-)；[Inno Setup 安装日志参数](https://jrsoftware.org/ishelp/topic_setupcmdline.htm)；[360 软件误报反馈](https://open.soft.360.cn/report.php)。向 360 提交反馈需由用户确认和提交，不代表已经认定此提示为误报。
