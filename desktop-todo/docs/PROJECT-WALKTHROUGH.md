# 项目讲解提纲

这份提纲用于准备技术交流，依据当前实现组织，不作为个人经历或独立完成程度的声明。

## 三分钟介绍

1. 展示周视图与任务时间轴：解释固定时间的安排和跨天任务为何放在两个视图中。
2. 演示编辑一个节点并撤销：说明预览、有效范围和一次操作对应一步历史。
3. 展示结构图：界面负责交互，Core 负责日期和状态处理，SQLite 负责持久化。
4. 打开一次实际 Actions 记录：说明哪些检查自动运行，哪些仍需要桌面实测。
5. 说明当前边界：单机使用、没有云同步，混合 DPI 与长期运行尚未全面覆盖。

## 建议先读懂的实现

- CalendarLogic：每周日程如何展开，“本次”与“本次及以后”如何修改。
- Store：为什么先提交数据库再移动撤销历史，为什么提醒去重记录不随内容撤销。
- ViewMath 与 TimelineView：视口平移与节点改期有什么区别。
- App 与 Native：托盘、窗口退出和桌面驻留各由哪里负责。

## 容易被追问的问题

- 为什么 SQLite 中保存完整 JSON，而不是把每个任务拆成多张关系表？适用规模和代价是什么？
- 60 项检查覆盖哪些失败条件？为什么不能把这个数量称作覆盖率？
- 程序关闭、电脑休眠或系统时间调整后，提醒会如何处理？
- 标准版与兼容版改变了什么？为什么不承诺所有机器均已验证？
- 如果要做跨设备同步，当前本地日期与整份状态保存会遇到哪些限制？

介绍贡献时只陈述实际做过、能够解释的工作；尚未理解的实现应先阅读和实验，不必用夸大的术语包装。
